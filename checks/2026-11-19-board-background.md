# 检查：看板在后台跑，配对不用管（1.8.11）

在公司电脑上走一遍。每一步拍照发回。

## 第 0 步：以前是不是同时跑了两个看板（还在 1.8.10 或更早时）

更新之前，先在 PowerShell 里运行：

```powershell
netstat -ano | findstr :8765
```

拍照。如果有两行 `LISTENING`，最后一列是两个不同的数字，就说明以前确实同时跑了两个看板。

## 准备

1. 停掉所有看板：关掉所有 Start Harness 的窗口。再运行一次上面的 `netstat`，确认什么都不输出；还有输出的话，按最后那列的数字结束进程：

   ```powershell
   Stop-Process -Id <那个数字>
   ```

2. 更新到 1.8.11（用文件夹更新，或者在 harness 文件夹里运行 `git pull`），然后运行：

   ```powershell
   harness --version
   ```

   应该显示 `1.8.11`。拍照。

## 第 1 步：双击启动

双击 Start Harness（`.cmd` 或者那个带机器人图标的快捷方式）。

应该看到：
- 窗口里有转圈和秒数，依次是：`starting the board` → `waiting for the browser to open the page` → `pairing`。记下每一段大概多少秒，拍一张。
- 浏览器打开看板，已经配好对（进入页上 `Browser paired` 是绿的）。
- 页面打开以后，启动窗口自己关掉。
- 没有一直开着的黑色终端窗口。
- 看板开着的几分钟里，留意有没有黑色窗口一下一下闪出来（看板在后台调用 git、VS Code 命令时）。有的话，拍下来，记下当时在做什么。

再运行一次 `netstat`，应该只有一行 `LISTENING`。拍照。

## 第 2 步：再双击一次

看板开着的时候，再双击一次 Start Harness。

应该看到：
- 窗口很快说看板已经在跑，然后关掉；
- 浏览器打开看板；看板没有重启：正在建的任务、Live 里的内容都还在；
- `netstat` 还是只有一行 `LISTENING`。

拍照。

## 第 3 步：停止，再启动，不用再配对

1. 点看板右上角的电源按钮。它会先问一句，点"确定"。页面上应该只剩一句：看板已停止，双击 Start Harness 再启动。拍照。
2. 再双击 Start Harness。
3. 回到原来那个浏览器标签页，刷新。应该直接能用，不要求配对。拍照。
4. 关掉整个浏览器，再打开看板地址 `http://127.0.0.1:8765/`。还是配好对的。拍照。

## 第 4 步：一键配对

用一个没配对过的浏览器打开 `http://127.0.0.1:8765/`：Edge 的 InPrivate 窗口，或者另一个浏览器。

应该看到：
- 页面上方写着没有配对，旁边有 `Pair this browser` 按钮。拍照。
- 点这个按钮：默认浏览器打开一个新的看板页面，已经配好对。拍照。
- 不需要碰任何终端。

## 第 5 步：日志

打开 harness 文件夹里的 `.harness\runtime\board.log`。里面应该有看板的输出，没有 `pair=`。拍一张开头。

## 发回

每一步的照片。如果第 1 步的转圈卡在某一段超过 3 分钟，拍下窗口里最后写的话。
