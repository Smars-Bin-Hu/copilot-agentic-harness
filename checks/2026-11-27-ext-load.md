# 检查：在公司电脑上真的加载一次 Copilot 扩展，量 hook 的时间

上一个检查（只看不改）的结论：公司电脑的 VS Code 是 1.148，有扩展这套东西，也没有策略禁止。这一次真的加载一个，回答三件事：

1. **能不能加载**：Windows 加上公司的环境（代理、安全软件），扩展进程起不起得来，要多久。
2. **它的答复算不算数**：扩展说「拒绝」时调用是不是真的被拒绝；扩展不答、命令 hook 说「拒绝」时，是不是也被拒绝。
3. **快多少**：同一个调用里，命令 hook 从开始到 Python 跑起来要多久（起进程的成本），扩展从被调用到答完要多久。扩展里顺带和看板的判断服务握一次手（不判断任何调用），量一下这条路要多久。

## 这个脚本做什么，不做什么

- 在 TEMP 里新建一个空文件夹 `harness-ext-probe\run-<随机6位>`，里面只有两个探针，挂在 PreToolUse 上：
  - 一个命令 hook：每次调用起一次 `python -S probe_hook.py`，起法和 harness 的 hook 一样；
  - 一个扩展：每个聊天一个 Node 进程，hook 是它里面的一次函数调用。
  - 两个都只记时间，不判断别的。命令 hook 只拒绝带 `CMD-PROBE-DENY` 的命令，扩展只拒绝带 `EXT-PROBE-DENY` 的命令。
- 它连的是**看板已经起好的那个 agent host**。它先记下 `canvasesEnabled` 原来的值，再把它设成真（host 只有在这个值为真时才加载扩展），并声明信任这个探针文件夹。跑完把值改回原样。
- 在探针文件夹里开**一个**聊天（Copilot Fusion，Allow all），让它一条一条地跑 7 条 `echo`。就这一轮，花几个 credits。最多等 6 分钟。
- **不碰 harness 文件夹**，也不碰它的任务、hook 和 gate。harness 文件夹里没有扩展，所以把 `canvasesEnabled` 打开不影响正在跑的任务。
- 只打印时间、次数和探针用的那几个词。路径只出现探针文件夹（用户目录显示成 `~`），不打印其他聊天的内容。
- 如果 VS Code 的企业策略 `ChatCanvases` 被设成关，脚本第一段就停下，什么都不做。
- Python 3.9 就能跑。除了标准库，只用 harness 自己的 `core.ahp`（看板连 agent host 用的那一个），所以要在 harness 文件夹里运行。

## 步骤

1. **先看 VS Code 的设置**：在 VS Code 里打开 Settings，搜 `chat.canvases.enabled`，拍下这一项。
   - 如果它旁边写着由组织管理（managed by your organization）而且是关的：**到此为止**，不要做后面的步骤，把照片发回。组织不让用，我们就不从看板这边绕过去。
2. 打开看板（`harness task board`），等它显示出任务列表。
3. 在 GitHub 上打开这个分支的 `checks/2026-11-27-ext-load.py`，存进 **harness 文件夹**（和 `.harness` 在同一层）。
4. 在 PowerShell 里进到 harness 文件夹，把窗口拉宽（一行约 160 个字符），运行：

   ```powershell
   python .\2026-11-27-ext-load.py
   ```

   找不到 `python` 时改用 `py -3 .\2026-11-27-ext-load.py`。正常要 1 到 3 分钟。
5. 把输出拍照或截图发回。约 35 行，一屏放不下就分几张。**第 0 段和第 1 段的每一行**都要拍清楚。
6. 用完后删掉 harness 文件夹里的 `2026-11-27-ext-load.py`。探针文件夹可以留着，下一次运行会把它清掉。

## 出了问题

- 报错：把报错那一屏拍下来发回，不用自己修。
- `No agent host record`：看板没开，或者还没起好。打开看板，等任务列表出来，再运行一次。
- 第 0 段 `probe folder trusted False`：照样拍照发回。
- 出现 `could not put canvasesEnabled back`：关掉看板再打开就恢复了（看板会起一个新的 host，值回到默认）。也拍下来发回。

## 发回来以后看什么

**第 0 段**

| 一行 | 怎么读 |
| --- | --- |
| `VS Code policy ChatCanvases` | `not set`：组织没设这条策略 |
| `canvasesEnabled before … -> now True` | 原来的值，和改过之后的值 |
| `probe folder trusted` | `True`：host 认这个文件夹（1.148 只对受信任的文件夹跑项目里的 hook） |
| `chat state at the end` | 应该是 `7 tool calls done` |
| `canvasesEnabled put back to` | 跑完恢复成了什么，应该和 before 一样（`None` 会写回 `False`，也就是默认值） |

**第 1 段：能不能加载**

| 一行 | 怎么读 |
| --- | --- |
| `load 1 / joined 1` | 扩展起来了，接上了这个聊天。**`load 0` 就是没起来**，这时看下一行 |
| `Copilot log lines since the start` | `prohibited` 大于 0：被策略禁了；`unresolved` 大于 0：策略没拿到 |
| `seconds from asking the host to the extension's first line` | 从开聊天到扩展进程跑起来要几秒（一个聊天只起一次） |
| `command hook ran 7 times` | 命令 hook 每个调用都跑了 |

**第 2 段：每个调用一行**，单位是毫秒，从 Copilot 开始这次 preToolUse 算起：

- `cmd>`：Python 跑到第一行，也就是起进程花了多久；`cmd<`：Python 跑完；
- `ext>`：Copilot 调用扩展；`ext<`：扩展答完；`hello`：和看板握手用了多久；
- `end`：Copilot 这一次 hook 结束；
- `result`：`ran` 照常执行，`denied:ext` 被扩展拒绝，`denied:cmd` 被命令 hook 拒绝。

**两个拒绝要对上**：`EXT-PROBE-DENY` 那一行是 `denied:ext`，`CMD-PROBE-DENY` 那一行是 `denied:cmd`。后一条说明扩展不答的时候，命令 hook 的拒绝照样算数。

**第 3 段：汇总**。要比的是两行：

- `command hook: until python's first line`：每个调用起一次 Python 的成本；
- `extension part: Copilot's call -> hook end`：扩展这一段从头到尾的成本。

Mac 上的样子（VS Code 1.147，模拟公司电脑速度的设置全关）：

- 扩展：起来要 9.5 秒（每个聊天一次）；`extension part` 中位 66 ms；握手中位 21 ms。
- 命令 hook：到 Python 第一行中位 167 ms。
- Copilot 先跑命令 hook，等它结束才调用扩展，两段是一前一后。
- 两个拒绝都对得上。

公司电脑上的看点：这个探针 hook 本身几乎不干活，所以 `cmd>` 主要就是起进程的成本，之前量过约 1.5 秒；`extension part` 能不能保持在几十毫秒。
