# 检查：慢在哪（`harness speed`，1.8.24）

在公司电脑上走一遍，每一步拍照发回。命令都在 harness 文件夹的 PowerShell 里运行。

## 准备

1. 点看板右上角的电源按钮，停掉看板。
2. 更新到 1.8.24，运行 `harness --version`，应该显示 `1.8.24`。
3. 双击 Start Harness，等看板起来。

## 第 1 步：空闲时跑一次

所有 agent 都停着的时候运行：

```powershell
Measure-Command { harness speed | Out-Host }
```

- 拍下整个输出，包括最后的 `TotalSeconds`（这次运行用了多久，应该在 60 秒以内）。
- 看"现在"那一段：
  - "启动一个进程"是几秒；
  - CPU、内存；
  - "最忙的"里有哪些程序。
- 看"网络"那一段：
  - 是不是"经代理"；
  - 有没有"Python 不信任服务器的证书"；
  - 有没有"量不出来"。

## 第 2 步：VS Code 启动到连上

1. 关掉 VS Code。
2. 在看板上点"打开 VS Code"，记下大概多久 Enter 页的 VS Code 那一行变绿。
3. 变绿后再跑一次 `harness speed`。最后那段"VS Code 启动到连上"应该有一个秒数，和你记的差不多。拍照。

## 第 3 步：高峰时跑一次

1. 让 5 个 agent 同时干活（5 个任务各发一句话，让它们都在跑）。
2. 它们都在跑的时候运行：

   ```powershell
   Measure-Command { harness speed | Out-Host }
   ```

3. 拍下整个输出。"现在"和"网络"两段里，每个数字后面会写出空闲时的值，例如"（上次 1.4 s）"。

## 第 4 步（可选）：正常用一天以后

正常干一天活以后再跑一次 `harness speed`，拍照。历史那张表里，"同时 2-3 个"和"4 个以上"两列的调用次数多了，结论才可信；每组至少要 20 次调用。

## 发回

- 第 1、3、4 步的整个输出；
- 第 2 步你记的秒数和输出最后一段；
- 哪一步的数字看起来不对（例如 CPU 是 0%、内存是空的、最忙的程序一个都没有）：Windows 上那几项是第一次真正运行。
