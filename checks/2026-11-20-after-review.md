# 检查：已关闭任务的事后检查，和重开时 DEV 改名（1.8.16）

在公司电脑上走一遍。每一步拍照发回。`<任务名>` 换成你电脑上真实的任务名。

## 准备

1. 点看板右上角的电源按钮停掉看板。
2. 更新到 1.8.16，然后运行 `harness --version`，应该显示 `1.8.16`。拍照。
3. 重新双击 Start Harness，进看板。
4. 找两个**已关闭、没做过独立检查**的任务，记作 A 和 B。A 最好是已 promote 过的开发任务。

## 第 1 步：在聊天里给已关闭的任务 A 做 2 次检查

1. 在 Copilot 里开一个新聊天（不要接上任何任务），写：

   ```text
   [review]=2 给已关闭的任务 <任务A名> 做独立检查
   ```

应该看到：
- agent 运行 `harness task review after <任务A名> --session-id …`，**没有**运行 `task open`。拍照。
- 然后它运行 `harness task review start --task <任务A名>`，调用 reviewer，一共两次。
- 看板上 A 还是"已关闭"。打开 A 的页面 →"结果"→"检查"：下面有一块"事后检查"，写着"要求 2 次"，有两轮结论。拍照。
- A 的"结果"里没有出现 `DEV_r1`，"文件"里的 `DEV` 还在。

## 第 2 步：在任务页上给 B 设检查

1. 打开 B 的页面，页头有一个盾牌按钮，名字是"事后检查"。点开，选 1。拍照。
2. 在 Copilot 新聊天里写（**不写** `[review]`）：

   ```text
   检查一下已关闭的任务 <任务B名>
   ```

应该看到：agent 运行 `task review after`，跑一次 reviewer。B 的页面"事后检查"一块里有一轮结论。拍照。

## 第 3 步：没有要求时，agent 开不了

在 Copilot 新聊天里写（不写 `[review]`，也不在页面上设）：

```text
给已关闭的任务 <另一个已关闭的任务名> 做独立检查
```

应该看到：`task review after` 被拒，原话是"用户没有要求检查已关闭的任务……"，agent 停下来告诉你怎么开。拍照。

## 第 4 步：重开任务时 DEV 被占用

1. 找一个已 promote、已关闭、**可以重开**的任务 C（重开会开始新一轮）。
2. 在资源管理器里打开它的 `DEV` 文件夹，不要关。
3. 在 harness 文件夹的 PowerShell 里运行（`<会话id>` 用 Copilot 聊天提示规则顶上写的那个，或者直接让 agent 运行 `task open`）：

   ```powershell
   harness task open <任务C名> --session-id <会话id>
   ```

应该看到：大约 5 秒后报错，是一句中文："<任务C名> 没能开始新一轮：Windows 不让把 … 改名成 …"，**没有** `WinError`。拍照。

4. 关掉资源管理器窗口，再运行一次同一条命令。

应该看到：成功，`round` 是 2。拍照。

## 发回

每一步的照片。第 1 步如果 agent 还是去 `task open`，把它那一轮回答全文拍下来。
